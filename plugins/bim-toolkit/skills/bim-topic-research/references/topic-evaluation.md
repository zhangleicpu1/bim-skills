# 选题评估与常见驳回原因（topic-evaluation）

选题不是「找个方向把模型建出来」，而是**回答一个有边界的问题**。这一节给出评估尺度和评审最常挑的毛病。

---

## 一、四维评估尺

选题理由必须同时立住这四条，缺一条评审就会追问。

| 维度 | 要回答的问题 | 不合格的表现 |
| --- | --- | --- |
| **案例支撑** | 有人做过吗？做到什么程度？ | 只有一两条新闻线索，说不出技术细节 |
| **痛点真实** | 要解决的是真痛点还是想象的痛点？ | 痛点是「效率低、协同难」这类放之四海皆准的空话 |
| **可行性** | 数据拿得到吗？团队做得出来吗？时间够吗？ | 数据来源未落实；工作量明显超出周期 |
| **创新点** | 别人没做过的那一点是什么？ | 只是把已有做法换个项目重做一遍 |

**最危险的组合**：案例支撑强 + 痛点真实 + 可行 + **无创新**。这种选题做出来是一份漂亮的工程实践报告，不是研究。补救方向是把范围收窄到一个可对照测量的变量上。

---

## 二、选题收窄法

多数选题死在「太大」。收窄的四个手法：

| 手法 | 例子 |
| --- | --- |
| **收对象** | 「铀矿工程 BIM 应用」→「地浸采区集液管网 BIM 建模」 |
| **收环节** | 「BIM 全生命周期应用」→「仅设计阶段的碰撞前置」 |
| **收变量** | 「标准化元件库应用」→「元件库对建模错误率与工时的量化影响」 |
| **收指标** | 「提升施工效率」→「碰撞点从 N 处降至 M 处，闭合率 X%」 |

**判断标准**：收窄后的选题能不能用一句话说清「我要测什么、跟什么比」？能，就收够窄了。

---

## 三、创新点的四种来源

找不到创新点，从这四个口子里挑一个：

1. **新对象**：已有方法用在新工程类型上（如把建筑领域的管线综合方法迁移到水冶厂工艺管道）
2. **新组合**：两种已有技术首次组合（如 BIM + 点云用于既有铀矿厂房改造）
3. **新变量**：把行业默认的前提拆开做对照实验（如元件库到底带来多少收益——这正是公开报道普遍跳过的一环）
4. **新工具**：二次开发解决一个具体痛点（如高支模立杆自动排布插件）

**注意**：技术堆砌不是创新。「BIM + 物联网 + AI + 数字孪生 + 区块链」堆五个词，做出来一个都不深，评审一眼看穿。

---

## 四、预期成果的量化要求

| 写法 | 判定 |
| --- | --- |
| `提升建模效率` | ✗ 不可量化 |
| `提高管理精度` | ✗ 不可量化 |
| `加深对 BIM 的理解` | ✗ 不是成果 |
| `建模工时由 X 小时降至 Y 小时` | ✓ 可量化、可复现 |
| `碰撞点由 N 处降至 M 处，闭合率 ≥ 90%` | ✓ 可量化 |
| `插件处理 1 组构件耗时由 X 分钟降至 Y 分钟` | ✓ 可量化 |

**原则**：**每一个指标都要能在交付时拿出数据证明。**开题时写不出来的指标，结题时也证明不了。

---

## 五、常见驳回原因（按出现频率排序）

1. **选题过大** —— 「基于 BIM 的智慧工地研究」这种题一听就知道做不深。见第二节收窄法。
2. **只有模型没有研究** —— 交了模型、动画、报表，但回答不了任何问题。这是最常见的死法。
3. **数据来源未落实** —— 图纸、勘察报告、设备清单没拿到就立项，第 5 周才发现做不下去。
4. **创新点说不清** —— 问「你的创新在哪」时答「我用了 BIM」。
5. **指标不可量化** —— 见第四节。
6. **案例来源不可查** —— 引用了一段没有出处的「某项目应用效果显著」。
7. **技术堆砌** —— 见第三节末。
8. **忽略行业特殊约束** —— 例如涉核工程遗漏辐射防护分区与通风气流的联合表达，安全工程遗漏疏散路径的规范依据。这类遗漏在评审中会被直接质疑专业能力。

---

## 六、开题前必答清单

交付选题报告前，确认自己答得上来：

- [ ] 这个选题要回答的**一个**核心问题是什么？
- [ ] 我要测的变量是什么，跟什么做对比？
- [ ] 数据从哪来，现在能拿到吗，书面授权有吗？
- [ ] 三个案例里，哪个是我最直接的对标对象，我比它多做了什么？
- [ ] 16 周内最坏情况下（数据延迟两周、建模卡壳一周）还能不能交付？
- [ ] 如果某个关键成果做不出来，降级方案是什么？
- [ ] 这个方向有没有行业强制规范必须遵守？我查过吗？

答不上第 1 条，回去重新收窄选题；答不上第 3 条，先解决数据再谈选题。
