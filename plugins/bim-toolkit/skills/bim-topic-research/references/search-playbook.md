# AI 检索策略（search-playbook）

选题调研的质量上限由检索质量决定。这一节规定：**检索怎么做、结果怎么筛、记录怎么写**。

---

## 一、硬约束

| 约束 | 要求 |
| --- | --- |
| 时间窗口 | 默认**近三年**（以调用时点往前推 36 个月）。经典方法类文献可放宽，但须单独标注年份 |
| 可回溯 | 每条案例必须能回溯到原始出处。**无来源 URL 的案例不得写入报告** |
| 不臆造 | 检索无结果时如实说明「该方向公开案例有限」，不得用相似方向的案例冒充 |
| 区分层级 | 明确区分「检索到的事实」与「基于事实的推断」，推断须在报告中标注 |

**最容易犯的错**：为了让报告看起来丰满，把某个案例的能力吹大，或把 A 项目的成果安到 B 项目上。宁可案例少，不可案例假。

---

## 二、关键词矩阵

单一检索式命中率很低。按下表做**组合式检索**，每格取 1—2 个词交叉。

| 维度 | 词表 |
| --- | --- |
| **对象词** | 铀矿工程、地浸采铀、天然铀产能、水冶厂、综合管廊、地下管线、盾构隧道、区间隧道、地铁车站、深基坑、支护结构、围护结构、地下连续墙、既有建筑改造、老旧小区、医疗建筑、装配式、钢结构 |
| **技术词** | BIM、建筑信息模型、三维正向设计、数字化交付、数字孪生、三维激光扫描、点云、实景三维、协同设计、参数化建模、BIM 二次开发、Dynamo、Revit 插件、BIM+GIS、BIM+物联网 |
| **动作词** | 应用案例、应用研究、工程实践、试点、示范工程、获奖、验收、上线、部署、收官 |
| **价值词** | 碰撞检查、管线综合、净高优化、工程量核算、竣工结算、施工模拟、进度管控、质量管控、监测预警、运维管理、降本增效 |
| **身份词** | 中核、中建、中铁、中冶、中交、中电建、省地质局、市政集团、地铁集团 |

**组合示例**（可直接复用）：

```
{BIM 三维正向设计} + {天然铀产能} + {数字化交付}
{BIM 管线综合} + {综合管廊} + {施工优化}
{三维激光扫描} + {盾构隧道} + {质量监控}
{BIM 物联网} + {深基坑} + {监测预警}
{三维激光扫描} + {既有建筑改造} + {深化设计}
```

## 三、检索源优先级

| 层级 | 来源 | 用途 | 证据等级 |
| --- | --- | --- | --- |
| 一 | 企业官网 / 官微、政府网站（住建、自然资源、数据管理局）、核心期刊（万方/知网/维普） | 直接引用为论据 | **A** |
| 二 | 行业媒体报道（科技日报、中国经济网）、学术会议论文、竞赛获奖公示 | 需交叉验证后引用 | **B** |
| 三 | 自媒体、聚合平台、转载稿 | 仅作线索，追溯回一级来源才可用 | **C** |

**甲级证据的特征**：有具体项目名称、有明确单位、有可量化数据、有明确时间。若一条信息只有「某项目应用了 BIM 效果显著」而无上述任何一项，直接丢弃——这类内容对选题毫无帮助。

## 四、检索记录怎么填（报告第四章）

用户明确要求输出「AI 检索记录」，这一章不是装饰，是**可复核性证明**。每条记录填 7 个字段：

| 字段 | 填写要求 |
| --- | --- |
| 检索式 | 写**实际使用的完整检索式**，不要写「BIM 相关关键词」这种模糊描述 |
| 检索源 | 具体到平台/站点，不要只写「网络」 |
| 时间范围 | 近三年 / 不限（并说明为什么放宽） |
| 命中数 | 该检索式返回的结果条数 |
| 采用数 | 实际进入报告的条数 |
| 筛选说明 | **保留了什么、剔除了什么、为什么** ——这一栏最能体现调研是否认真 |

**筛选说明的写法对比**：

- ✗ 太笼统：`剔除了不相关的 3 条`
- ✓ 可复核：`剔除 2 条转载内容重复项、1 条仅提及未展开的新闻；保留 1 条国际处置库 BIM 报道作为对标（国内案例不足，需横向参照）`

## 五、检索执行流程

```
第 1 轮：宽检索（对象词 + BIM）
   → 摸清该方向案例总量、主要实践单位、活跃年份
   → 若总量 < 3 条，说明方向冷门，改用宽口径并延长窗口

第 2 轮：窄检索（技术词 + 价值词）
   → 补齐技术细节：用了什么方法、解决了什么具体问题、数据指标如何

第 3 轮：反向检索（身份词 + 对象词）
   → 按已知实践单位反查，挖掘其同方向的其他项目

第 4 轮：约束检索（针对本选题的特定前提）
   → 例如核工程需查「辐射防护分区与通风气流联合表达」这类边界条件
```

**每轮都要记进检索记录表**，第 4 轮尤其容易被忽略——它往往决定选题是否可行。

## 六、检索失效时的处理

| 情况 | 处理 |
| --- | --- |
| 该方向案例极少（如铀矿、核工程） | 如实说明「公开案例稀缺」，并补充**国际对标**（如芬兰 Onkalo、德国 Konrad）与**邻近方向类比**（如核电站 BIM），但要明确标注这是类比不是同方向 |
| 只能找到新闻通稿、无技术细节 | 明确写出「公开报道只给结论不给方法，技术细节属企业技术资产」，并把选题重点转向可自主实现的部分 |
| 找不到近三年案例 | 放宽到近五年并说明放宽原因；若仍无，考虑换方向而不是硬凑 |
| 命中大量重复转载 | 用「原始出处 + 项目名」去重，只保留一级来源 |

---

## 七、写进报告前自检

交付前逐条过一遍：

- [ ] 每个案例都有可点击的来源 URL
- [ ] 每个案例都有明确年份，且落在检索窗口内
- [ ] 数据指标（数字、百分比）都来自原文，没有四舍五入放大
- [ ] 没有把「某企业能力」写成「行业普遍能力」
- [ ] 检索记录表里每个检索式都真实跑过
- [ ] 推断性内容（如「预计可提升效率 X%」）已明确标注为推断
