# 案例卡片规范（case-card-spec）

每个入选案例写成一张案例卡片。卡片是报告的原子单元，也是**未来复用的资产**——调研过的案例应回写进 `assets/case_library.json`，下次同类方向直接可用。

---

## 一、字段定义

| 字段 | 必填 | 填写要求 |
| --- | --- | --- |
| `title` | ✓ | 案例标题。用「项目特征 + 技术手段」结构，如「海力锦天然铀产能项目三维正向设计」 |
| `project` | ✓ | 建设单位 + 项目名称，能定位到具体工程 |
| `year` | ✓ | 年份或年份区间。区间写法如 `2024—2026`；跨年持续项目标 `2023—（持续）` |
| `source` | ✓ | 来源全称，注明发布主体与性质（如「企业官方报道」「核心期刊论文」） |
| `url` | ✓ | **可访问的原始出处链接**。无 URL 的案例不得进入报告 |
| `problem` | ✓ | 解决了什么问题。**2—5 句**，写清痛点的成因，不要只写「效率低」 |
| `modeling_points` | ✓ | 可借鉴的建模点。**4—6 条**，每条是一个可操作的技术动作，不是泛泛的目标 |
| `data_points` | 建议 | 可引用的关键数据。**原文数字直接抄，不做换算放大** |
| `fit_for_topic` | 建议 | 选题适配建议。说明这个案例适合衍生出什么类型、什么难度的选题 |

---

## 二、`problem` 怎么写

问题描述要有**因果链**，读的人才知道痛点从哪来。

- ✗ 只写症状：`管线碰撞多，施工返工严重`
- ✓ 带出成因：`天然铀产能项目专业门类多、流程长，传统二维设计各专业串行提资，管道密集区域在图纸上无法表达空间关系，导致管线碰撞与净空不足往往到施工阶段才暴露；涉核工程设计变更管控严，一次返工代价远高于常规民用工程`

判断标准：**把成因删掉后，如果这句话对任何工程都成立，说明写得太泛了。**

---

## 三、`modeling_points` 怎么写

每条必须是一个**可执行的技术动作**，带对象、带手段。

- ✗ 目标式（写了等于没写）：`实现管线综合优化`、`提高模型精度`、`加强协同`
- ✓ 动作式：
  - `项目级标准化元件库：细分 22 个管道等级、内置 32 类 3000 余种核心元件及其适配参数，从源头消灭『经验选型』`
  - `监测点模型与实体模型关联绑定：测点在模型里有位置、有身份，预警时能在模型里定位`
  - `Revit 建结构体 + Civil 3D 建地质体的分工建模法：解决『结构好建、地质难建』的问题`

**自检**：这条建模点能不能转成一句任务派给组员？如果不能，说明它还是口号。

---

## 四、证据强度分级

| 等级 | 来源特征 | 使用方式 |
| --- | --- | --- |
| **A** | 企业官方发布、政府网站通报、核心期刊论文 | 可直接作论据引用 |
| **B** | 行业媒体报道、会议论文、竞赛获奖公示 | 需第二来源交叉验证 |
| **C** | 自媒体、聚合平台转载 | 仅作线索，追溯回一级来源后才可用 |

报告中案例应尽量由 A 级构成。若全部案例只能到 B 级以下，须在检索记录里说明原因。

---

## 五、入库回写规则

调研完成后，把新案例按以下规则回写 `assets/case_library.json`：

1. **去重**：按 `project` 名称去重，同一项目的多篇报道合并为一张卡片
2. **归方向**：放入 `directions` 下已有方向；若是新方向，按现有结构新建（含 `aliases` 与 `keywords`）
3. **补别名**：新方向务必补齐 `aliases`，否则下次用户换个说法就命中不到
4. **标记时效**：`year` 字段必填，便于后续按窗口自动淘汰过期案例
5. **不删旧项**：旧案例改用年份标注保留，不做删除——经典案例的价值不随时间衰减

---

## 六、卡片质量红线

出现以下任一情况，卡片不得进入报告：

- 无 `url`，或 URL 已失效无法访问
- `year` 缺失或无法判断是否落在检索窗口内
- `problem` 只有症状没有成因，或删掉成因后适用于任何工程
- `modeling_points` 全是目标式表述，无一条可执行动作
- `data_points` 中的数字在原文中找不到
- 把某企业自研能力表述为行业普适做法
