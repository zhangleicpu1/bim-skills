# BIM 专项可视化助手

## 用途

把「我要在 XX 项目中做 XX 专项的可视化」这类需求，转成一套可执行的表达方案。

核心判断：**专项可视化的难点不在软件操作，在于「用什么颜色、怎么标注、按什么规范」这三件事没有标准答案**。本 Skill 提供一套带依据的默认答案，让方案从「讨论起点」而不是「空白页」开始。

产物：
- **HTML 方案书**（自带真实色块，可直接打开/打印/发给团队）—— 8 个章节覆盖全部要求
- **Markdown 检查清单**（可勾选，用于出图前自检）

## 触发方式

用户表述通常长这样：

- 「我要在 XX 铀矿项目中做辐射防护分区的可视化」
- 「XX 管廊项目的管线综合怎么配色」
- 「基坑支护的支护结构可视化方案」
- 「教学楼的疏散路线怎么做图」
- 也可能只说专项不说项目：「疏散路线怎么可视化」

**项目类型与专项内容任一缺失时，先按知识库推断，推断不出再问**，不要一上来就追问。例如用户说「辐射防护分区」，可直接判定为铀矿/核工业场景；说「管线综合」可判定为管廊或民建机电。

## 执行流程

### 第 1 步：识别项目类型与专项内容

从用户表述中抽取两个要素。项目类型与专项都可能出现同义说法，需归一：

| 用户可能说 | 归一为 |
| --- | --- |
| 铀矿、铀矿冶、放射性矿山 | 铀矿工程 |
| 管廊、综合管廊、电缆管廊 | 地下综合管廊 |
| 盾构、地铁隧道、区间隧道 | 盾构隧道 |
| 深基坑、基坑、边坡支护 | 基坑支护 |
| 学校、中学、小学、实验楼 | 教学楼 |
| 别墅、联排、叠拼 | 双拼别墅 |
| 纪念碑、纪念广场、雕塑 | 英雄纪念碑 |
| 射线分区、防护分区、辐射分区 | 辐射防护分区 |
| 管综、管线排布、碰撞检测可视化 | 管线综合 |
| 锚喷支护、巷道支护、围岩支护 | 支护结构 |
| 消防疏散、逃生路线、安全疏散 | 疏散路线 |

知识库中每个专项都有 `aka` 别名表，脚本会自动匹配，不必手工对照。

### 第 2 步：查知识库并生成方案

```bash
PY="C:/Users/52248/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
SKILL="C:/Users/52248/.workbuddy/skills/bim-topic-visualization"

# 查看已收录的项目类型与专项
"$PY" "$SKILL/scripts/build_scheme.py" --list

# 生成方案书
"$PY" "$SKILL/scripts/build_scheme.py" \
  --project "铀矿工程" --topic "辐射防护分区" --name "XX矿采冶工程" -o "<输出目录>"
```

参数：

| 参数 | 说明 |
| --- | --- |
| `--project` | 项目类型（必填） |
| `--topic` | 专项内容（必填） |
| `--name` | 项目名称，用于文件命名与标题；缺省用项目类型 |
| `-o/--outdir` | 输出目录 |
| `--list` | 列出知识库覆盖范围 |

脚本只用 Python 标准库，无需安装任何依赖。

读 stdout JSON 确认 `topic_in_kb`：
- `true` → 命中知识库，方案完整，直接进入交付
- `false` → 专项未收录，脚本已回退到通用色板与通用方法，`note` 字段会提示。此时应**主动补充**该项目类型的专项方案（见「扩展知识库」）

### 第 3 步：在回复中给出方案要点

用户要的是方案本身，不是「文件已生成」。回复中必须把七项内容讲清楚：

1. **可视化方案** —— 推荐哪几种表达图（轴测图 / 分层剖切 / 剖面 / 云图 / 动画），各自解决什么问题
2. **颜色映射表** —— 分区/等级与颜色的对应，用文字或表格列出色值与含义
3. **图例说明** —— 位置、尺寸、必含内容
4. **视图设置步骤** —— Revit 与 Navisworks 的关键操作（详细步骤指向 `references/view-setup.md`）
5. **标注要求** —— 该专项哪些必须标、格式如何
6. **出图规范** —— 比例、图幅、标题栏、线宽
7. **检查清单** —— 通用项 + 专项项，逐条可勾选

回复应聚焦该项目/专项的**特殊性**，通用制图常识不必展开。例如辐射防护分区要强调「必须与通风气流联合表达」，管线综合要强调「电力与消防红色冲突需用线型区分」。

### 第 4 步：交付文件

用 `present_files` 呈现 HTML 方案书与 Markdown 检查清单，**HTML 放最前**（会自动打开预览，色块可见）。

**HTML 方案书本身就是一份「专项配色对照表」草案**，提醒用户确认后固化为项目标准，后续所有图纸从该表取值。

## 关于颜色依据的诚实边界（重要）

知识库中每个专项都标注了 `authority` 字段，涉及法律效力，**回复时必须如实传达**：

| 等级 | 含义 | 本项目中的典型场景 |
| --- | --- | --- |
| 强制性 | 国标强制规定，不得擅改 | 安全出口绿色（GB 13495.1）、安全标志四色（GB 2894） |
| 推荐 | 有规范依据或行业公认做法 | 辐射防护分区三色、地质分层色（须与勘察报告一致） |
| 行业惯例 | 无规范条文，必须与项目既有标准统一 | 管线类型色、支护构件色、云图色阶、功能分区色 |

**绝对不能把行业惯例说成规范强制。** 例如「给水蓝、排水绿、电力红」是市政行业通行做法，不是国标规定的色值。正确的表述是：

> 这套配色是行业通行做法，规范未强制规定色值。如果贵司或当地管线管理部门有既定标准，以既有标准为准；确认后建议固化为项目标准。

规范的检索清单见 `references/color-principles.md`，其中列出了各专项对应的规范编号与约束内容。

## 扩展知识库

遇到未收录的项目类型或专项，直接扩充 `assets/visualization_kb.json`（这是唯一的数据源，脚本、方案书、检查清单全部由它驱动）：

| 要加什么 | 改哪里 |
| --- | --- |
| 新的专项 | `topics` 下新增一个键，参考已有条目结构 |
| 新的项目类型 | `project_types` 下新增，含 `traits`、`default_topics`、`notes` |
| 特定组合的特殊要求 | `combinations` 下新增，键格式为 `"项目类型\|专项"` |
| 调整通用图例/出图/检查清单 | `defaults` 节点 |

新增专项时的必填字段：`aka`、`domain`、`standard`、`authority`、`authority_note`、`palette`（或 `gradient`）、`methods`、`legend`、`annotation`、`view_focus`、`checklist`、`pitfalls`。

只使用连续色阶的专项，把 `palette` 显式设为 `[]` 并提供 `gradient` —— 脚本会区分「空色板」与「未收录」两种情况。

## 故障排查

| 现象 | 处理 |
| --- | --- |
| 退出码 2 | 未提供 `--project` 或 `--topic`，用 `--list` 查看已收录内容 |
| 方案书缺少颜色 | 该专项只用连续色阶（`palette` 为空），属正常，色阶在第二章下方 |
| 检查清单只有 10 项 | 专项未收录，只输出了通用 10 项；按上文扩充知识库 |
| 用户给的项目类型不在列表中 | 先按领域归入最接近的项目类型生成，再在回复中说明并补录知识库 |
| HTML 打开后色块不显示 | 检查是否被浏览器拦截了内联样式；文件为纯静态自包含 HTML，无外部依赖 |

## 配套文件

- `scripts/build_scheme.py` —— 方案书生成器（纯标准库，无依赖）
- `assets/visualization_kb.json` —— 知识库唯一数据源：项目类型、专项色板、表达方法、检查清单
- `references/view-setup.md` —— Revit / Navisworks 视图设置操作细则（过滤器、视图样板、Appearance Profiler、剖切、碰撞结果可视化）
- `references/annotation-and-drawing.md` —— 标注三层级、引线规则、出图比例图幅线宽、图纸配套关系
- `references/color-principles.md` —— 颜色的三种法律地位、配色设计原则（黑白测试、色盲友好）、规范引用清单
