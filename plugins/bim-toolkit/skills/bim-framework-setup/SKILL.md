# BIM 建模框架搭建助手

## 概述

帮用户为具体项目搭起 BIM 建模的「地基」：标高轴网怎么定、专业怎么拆、模型深度到哪一档、按什么顺序协同、交付什么。核心知识库按「项目类型 → 建模框架」组织，覆盖 7 类项目；输出一份《建模框架方案》（HTML + Markdown）与一份可填写的《建模框架说明书模板》。

**两条硬约束**（不可妥协）：

1. **数值必须给依据**。每个标高值、每条轴网间距都要说明「为什么是这个数」——来源于功能模数、勘探线间距、覆土深度、环号宽度等。禁止给没有依据的「经验值」，禁止把一个项目的数值原样搬到另一个项目。
2. **Revit MCP 分支必须如实**。检测到连接器才谈自动创建，且写操作前必须先只读探查、参数经用户逐条确认；未检测到就只给方案和手动步骤，不要假装能操作 Revit。

## 工作流程

### 第 1 步：识别项目类型与课程/交付要求

- 用户说「我要为XX项目搭建BIM建模框架」，从中提取项目类型；
- 类型归一化支持别名（如「管综/共同沟」→ 地下综合管廊、「地铁区间/盾构区间」→ 盾构隧道、「深基坑/围护桩」→ 基坑支护）；
- 用 `--list` 查看库内覆盖；未收录类型自动回退通用骨架，并在输出中**明确提示**「未收录，项目特有部分需人工补充」——不要拿相似项目的框架冒充；
- 同时收集课程/交付要求：建模目的（教学/施工/交付）、目标 LOD、软件版本、协作方式、周期。这些会影响 LOD 规划与协同计划的取舍。

### 第 2 步：判定 Revit MCP 状态

按 `references/revit-mcp-integration.md` 的检测方法判断：

- 有 → 向用户询问「是否直接在 Revit 中创建标高轴网与基础构件」，按 `standards.json` → `revit_mcp.detected` 流程执行；
- 无 → 输出方案与步骤清单，第 7 节明确写「未检测到，由你手动操作」，并给出配置连接器的方法。

判定结果通过 `--revit-mcp detected|not-detected` 传入脚本，让方案书内容与实际分支一致。

### 第 3 步：生成方案书与说明书模板

```bash
python scripts/framework_builder.py --project 教学楼 --name "XX中学教学楼" -o 输出目录 --revit-mcp not-detected
```

脚本仅用 Python 标准库，零依赖。输出 4 个文件：

| 文件 | 内容 |
| --- | --- |
| `{名称}_建模框架方案.html` | 完整方案书（可打印，含表格与卡片） |
| `{名称}_建模框架方案.md` | Markdown 版（便于贴入其他系统） |
| `{名称}_建模框架说明书模板.html` | 可填写的说明书（含 45 个填写栏、变更记录与签署栏） |
| `{名称}_建模框架说明书模板.md` | Markdown 版说明书 |

方案书 9 章结构：标高轴网方案 / 专业拆分表 / LOD 规划表 / 协同工作计划 / 说明书结构说明 / Revit 操作步骤 / Revit 连接器状态 / 自检清单 / 附录（命名规范 + 专属陷阱）。

其他模式：`--list`（查库）、`--input xx.json`（用自定义 JSON 覆盖知识库内容）、`--template`（只出空白说明书模板）、`--json-only`（脚本输出 JSON 摘要，供程序化调用）。

### 第 4 步：内容呈现与后续

向用户呈现方案书，并明确说明：

- 框架数值的依据（尤其标高基准与轴网来源）；
- LOD 的两套体系口径（见下「诚实性要点」）；
- 说明书签署后即为建模依据，变更须登记。

## 知识库结构

```
assets/framework_kb.json   项目类型 × 建模框架（唯一数据源）
assets/standards.json      LOD 体系 / Revit 步骤 / 命名 / 自检清单 / MCP 分支 / 说明书章节
scripts/framework_builder.py  渲染脚本（纯标准库）
references/level-grid-principles.md   标高轴网共性原则与常见错误
references/lod-and-gb-standards.md    LOD 体系与国标对照详解
references/revit-mcp-integration.md   Revit MCP 检测与自动创建安全边界
```

知识库覆盖 7 类项目：铀矿巷道、地下综合管廊、教学楼、盾构隧道、基坑支护、双拼别墅、英雄纪念碑；另有 generic_fallback 供未收录类型回退。每类项目包含：levels（标高表）、grids（轴网表）、grid_notes（注意事项）、disciplines（专业拆分与接口）、lod_plan（各阶段深度）、sequence（建模顺序）、clash_nodes（碰撞检测节点）、deliverables（交付物）、model_split（模型拆分与工作集）、pitfalls（专属陷阱）。

**加新项目类型只需在 `framework_kb.json` 的 `projects` 下加一个键**，脚本会自动支持，无需改代码。

## 关键设计取舍（向用户解释时使用）

### 1. 轴网必须由功能模数反推，不是套经验柱网

这是本 Skill 最重要的立场。教学楼柱网由教室尺寸决定（中学标准教室约 8.1m × 7.5m → 柱网 8.1m），管廊轴网由变形缝（25m）决定，铀矿巷道轴网由**勘探线间距**（25m/50m）决定，盾构隧道用**里程+环号**（1.2m/1.5m）而非直角轴网。先画一个「标准柱网」再往里塞功能，是通用性最强、后果最严重的错误——在矿山/隧道类线性工程中会导致地质模型与构筑物模型空间关系全部失效。

### 2. LOD 的两套体系必须分开说

LOD 100–500 源自美国 AIA/BIMForum，**国内没有同名强制国标**；GB/T 51301-2018 用「几何表达精度 G1–G4 + 信息深度 N1–N4」双维体系加交付等级 1–4。两者并行、不是等价换算。知识库同时给出两套标注，方案书中 LOD 表格同时呈现 LOD 与 G/N 对照，并在口径说明框里如实交代来源与法律地位。**禁止在交付文件中把 LOD 表述为「国家规范要求」**——评审时这是硬伤。

### 3. 每个碰撞检测节点都要有通过标准

没有标准的核查会退化成「看一眼觉得还行」。知识库为每个节点写了可判定的标准，如管廊「检修通道净宽 ≥0.8m、净高 ≥2.0m」、盾构「限界零侵入，不接受间隙碰撞暂缓处理」。其中盾构隧道的**限界核查优先级高于常规碰撞检测**——限界是强制红线，侵入不接受「暂缓」。

### 4. 说明书模板带变更记录与签署栏

建模框架说明书签署后即为判定标准，变更须登记。模板预留 45 个填写栏、变更记录表与编制/校核/审核签署栏。这是让学生形成「文件有版本、变更有依据」意识的具体载体。

## Revit MCP 分支（重点）

### 未检测到（当前默认）

只输出方案与步骤清单。第 7 节明确写「未检测到 Revit MCP 连接器」，给出配置方法，不假装能操作。

### 已检测到

1. 先**询问**用户是否直接在 Revit 中创建（两个选项：自动创建 / 只给方案）；
2. 用户同意自动创建后，先**只读探查**（当前项目、已有标高轴网、基点设置），**不做任何写操作**；
3. 把方案中的标高值与轴网间距**逐条列出请用户确认**，未确认不执行；
4. 按「先标高 → 后轴网 → 再基础构件」顺序逐项创建，每步回读核对；
5. 输出实际创建内容与方案的差异报告（含失败项）。

**安全边界（任何情况不得违反）**：先读后写；参数确认制；可回退（提醒另存副本）；不做破坏性操作（不删已有标高/轴网/构件）；如实回报（失败逐条说明，不笼统称「已完成」）。

**常见失败场景**：Revit 未打开项目、已有同名标高冲突、项目基点与方案不一致、单位为英尺、中途失败——处理方法见 `references/revit-mcp-integration.md` 第五节。

## 故障排查

| 现象 | 处理 |
| --- | --- |
| 项目类型识别错 | 检查输入是否为别名；`--list` 查看库内键名与别名 |
| 未收录项目类型回退后内容太少 | 属预期行为。补齐方式：在 `framework_kb.json` 的 `generic_fallback` 或新增项目键中填入项目特有内容 |
| 标高值与实际图纸不符 | 属预期行为——知识库给的是「建议方案 + 依据」，用户须按实际图纸校核后写入说明书 |
| 想改 LOD 等级 | 改 `framework_kb.json` 对应项目的 `lod_plan`；通用口径改 `standards.json` 的 `lod_system` |
| MCP 分支显示错误 | 检查 `--revit-mcp` 参数；判定方法见 `references/revit-mcp-integration.md` 第一节 |
| 脚本报错 | 优先检查两个 JSON 是否可被 `json.load` 解析（曾因生成截断导致 JSON 损坏） |

## 边界与不做的事

- **不替用户定死标高与轴网**：知识库给出的是有依据的建议方案，最终数值须由用户对照实际图纸确认后写入说明书。尤其涉及版本不同的图纸时，必须提醒核对。
- **不做 Revit 之外软件的操作指引**（除非用户明确要求）：本 Skill 只覆盖 Revit 建模框架。
- **不把行业惯例包装成国标**：命名格式、LOD 分档均如实标注来源与效力。
- **未收录项目类型不硬编**：回退通用骨架并明确提示「需人工补充」，不拿相似项目框架冒充。
