# BIM 工程量统计助手

## 这个 Skill 解决什么问题

从 BIM 模型里取工程量，技术上「能取到」不是难点——**难点是取到的量能不能用**。

本 Skill 的核心立场：**Revit 明细表直出的是「模型实体净量」，清单工程量是「按计算规则计算量」。两者口径不同，必然有差，不是谁算错了。** 任何把模型量直接当清单量报出的做法都会在结算时出问题。

因此本 Skill 不只是「教你怎么建明细表」，而是把每个构件的**口径差异**讲清楚，并提供偏差分析的完整框架。

## 触发方式

- 「我要统计 XX 项目的工程量」
- 「混凝土/钢筋/土方/管道 的工程量怎么从模型里提」
- 「Revit 明细表怎么建」「明细表导出的数字加不起来」
- 「模型量和清单量为什么不一样」「模型量比手算少」
- 「帮我出一份工程量偏差分析报告模板」「工程量统计检查清单」

## 工作流程

1. **识别构件类型**——18 类，别名自动归一（371 个别名，含「混凝土」「钢筋」「地连墙」「管综」等口语说法）；未收录类型回退通用骨架并明确标注需补充确认；歧义说法（构造柱、钢支撑、阀门等）会提示备选构件
2. **输出本构件专属内容**——Revit 族类别与明细表类型、参数字段清单、过滤器与排序分组设置、计算值公式、提取要点、专属计价做法、专属陷阱、专属检查点
3. **叠加通用规范内容**——明细表创建 4 阶段 30 步、4 条取量路径对比、5 条成本关联路径、分类型偏差基准值、31 条常见错误、偏差分析报告 9 章模板、50 项检查清单
4. **生成三份文件**——HTML 方案书（9 章 16 表，可打印）、Markdown 方案、可勾选检查清单

## 命令行用法

脚本路径：`scripts/quantity_builder.py`，**纯 Python 标准库，零依赖**。

```bash
PY="C:/Users/52248/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
S="<skill_dir>/scripts/quantity_builder.py"

# 查看构件库
"$PY" "$S" --list

# 按构件类型生成（别名可用）
"$PY" "$S" --component 钢筋 --project "XX医院综合楼" --name "XX医院综合楼_钢筋" -o 输出目录
"$PY" "$S" --component 土方 --project "XX中心基坑" --name "XX中心基坑_土方" -o 输出目录

# 自定义输入（字段名见 assets/quantity_kb.json 的 components 结构）
"$PY" "$S" --input data.json --name "XX项目_混凝土" -o 输出目录

# 空白模板：all / checklist / deviation
"$PY" "$S" --template deviation --name "工程量偏差分析报告模板" -o 输出目录

# 机器可读结果
"$PY" "$S" --component 管道 --json-only
```

输出：
- `<name>_工程量统计方案.html` / `.md`
- `<name>_工程量统计检查清单.md`

## 输出内容结构（HTML 方案书 9 章）

1. **构件定位与统计概要**——族类别、明细表类型、要提供的计量项

3. **参数字段清单**——字段、单位、为什么需要它
4. **工程量提取方法**——本构件提取要点 + 4 条取量路径对比
5. **成本关联方式**——本构件计价做法 + 5 条通用关联路径 + 共享参数设计
6. **BIM 量 vs 清单量：口径差异**——本构件的口径差异详解 + 规范条款要点 + 分类型偏差基准值
7. **常见错误提醒**——本构件专属陷阱 + 4 组 31 条通用错误（模型侧 / 明细表侧 / 导出侧 / 口径侧）

9. **检查清单**——本构件检查点 + 6 节 50 项 + 出量前 QA 12 项

## 几个关键设计（使用时需要理解）

### 1. 每个构件都带 `bim_vs_boq` 字段

这是本 Skill 与「Revit 明细表教程」的根本区别。每个构件的口径差异都写明了具体来源、方向和量级。例如：

- **钢筋**：模型净量系统性偏小 10%~15%（不含搭接、弯钩、切割损耗）。有实例：明细表 96 t，实际下料 110 t
- **土方**：清单量不含工作面与放坡，定额量含 → 可差 20%~40%。**这两组数不能直接相减当作「偏差」**
- **管道**：清单不扣阀门管件（按延长米全长），而 Revit 管长与管件分开算 → 模型偏小 5%~15%
- **防水**：清单要求弯起部分并入，模型通常只建平面投影 → 偏小 10%~30%
- **支吊架**：模型中通常根本不存在 → 只能标注为「估算量」

### 2. 分类型偏差基准值（12 类）

**偏差率不能只看数值大小，要看与构件类型是否匹配。**

| 构件 | 正常范围 |
| --- | --- |
| 按樘/按个数计量 | ≤1% |
| 混凝土（总量） | ≤2% |
| 钢筋 | **10%~15%** |
| 机电管道 | ≤5% |
| 土方（清单 vs 定额） | **20%~40%** |
| 支吊架 | 无「正常偏差」概念，只能标注为估算量 |

钢筋偏差 12% 是正常的，门窗偏差 12% 是严重的。用统一的阈值筛选所有构件，会把正常现象当成问题，同时放过真正的问题。

### 3. 偏差原因是六类，不是一类

建模原因 / 口径原因 / 工艺原因 / 变更原因 / 数据原因 / 人为原因。

**把所有偏差都归为「建模误差」是最常见的归因错误**——大量偏差其实是口径差或工艺差，这些不需要「修正」，需要的是「说明」。归因错了，整改方向就错了。

### 4. 一条红线：导出后不得手工编辑数值

一旦在 Excel 里手改量，就破坏了 BIM 的单一数据源原则，后续每次重新导出都会产生新版本，越改越乱。需要调整只有三条合法路径：①回模型改；②建规则换算表显式写出换算（口径差）；③单独列「调整项」并注明依据与责任人。三条都要在报告附录说明。

### 5. 明确告知 BIM 算量的能力边界

方案书中如实写明：Revit 对国内清单定额计算规则支持度较弱；钢筋、模板、装饰面层是明确弱项（钢筋无成熟插件读取国内平法图纸，模板无专用工具，装饰面层提取面积可能不扣洞口）；Revit 插件算量的原理是模型映射，**构件定义与映射是否正确是量准不准的前提**。

## 故障排查

| 症状 | 处理 |
| --- | --- |
| 构件识别成「通用（未收录）」 | 该说法不在 371 个别名内。看 `--json-only` 输出确认，或直接改用 18 类的标准名；也可在 KB 的 `aliases` 里补充 |
| 方案里出现「该说法在库中同时挂在多个构件类型上」 | 属真实歧义（构造柱、钢支撑、阀门、钢筋网、保温层、圈梁、过梁、压顶）。用该构件的标准名重新生成 |
| 需要打印 | HTML 已含 `@media print` 样式，直接浏览器打印即可；建议 A4 纵向 |
| 想只出检查清单 | `--template checklist` |
| 想只出偏差分析报告模板 | `--template deviation` |
