# 模型量 vs 清单量：口径差异详解

> 本文是这个 Skill 的核心参考。**所有「偏差」判断的前提，是先确认两组数是不是同一个口径。**

## 一、为什么会不一样

Revit 明细表算的是**模型实体净量**（几何量，扣掉实体占位）。
清单算量是全套**简化的计算规则**（旨在统一各方口径，而非追求几何精确）。

清单规则为什么要简化？因为算量起源于手算时代。工程面积大、专业多，适当简化是必然选择——比如「抹灰不扣除 0.3 平方米以内的孔洞面积，洞口侧壁也不增加」「给排水管道不扣除阀门、管件所占长度」。严格说，简化后的量是**误差不大的错误工程量**；但只要参建各方统一规则，这个量就有可比性。

**规则一致比规则正确更重要。** 这就是为什么不能拿模型几何量直接替代清单量。

GB/T 50854-2024 里有一句话把这件事讲得很直白：**「计算规则优先于工程定额；设计图示尺寸优先于实物尺寸。」**

## 二、逐条对照表（按构件）

| 构件 | 清单规则 | Revit 明细表行为 | 结果 |
| --- | --- | --- | --- |
| 混凝土 | 不扣除构件内钢筋、预埋铁件、螺栓及单个面积≤0.3㎡的孔洞 | 按几何实体算，小孔洞可能已被扣除 | 双向小幅差异 |
| 混凝土（分项） | 柱算至柱顶/柱帽下表面；梁算至柱内侧边、次梁算至主梁侧边 | 由几何连接（Join）关系决定归属 | 分项差异，总量近似不变 |
| 钢筋 | 按设计图示长度乘理论质量，计入设计搭接 | 净长度，不含搭接、不含切割损耗 | **模型系统性偏小 10%~15%** |
| 钢结构 | 不扣除孔眼、切边，焊条铆钉螺栓不另增 | 按实体几何，孔洞若建模则扣除；节点多不建模 | 模型偏小（节点 3%~8%） |
| 砌体 | 扣除嵌入墙身的混凝土柱、梁、圈梁、挑梁、过梁及凹进墙内的壁龛、管槽 | 若墙未在构造柱位置断开，几何上可能仍含该部分 | 可能**重复计量** |
| 门窗 | 按洞口尺寸面积 或 按樘 | 族参数定义的面积（框外围/扇尺寸） | 面积口径差异；按樘计量差异极小 |
| 幕墙 | 按框外围尺寸以面积；与幕墙同材质的窗并入幕墙 | 嵌板分格面积 | 面积口径差异 + 异形龙骨缺失 |
| 楼地面 | 扣凸出构筑物、设备基础；不扣间壁墙、柱、垛；门洞开口部分不增加 | 房间面积按房间边界（净面积） | 扣减口径差异 |
| 防水 | 屋面卷材按图示尺寸面积；女儿墙、伸缩缝、天窗处**弯起部分并入** | 通常只建平面投影 | **模型偏小 10%~30%** |
| 墙面抹灰 | 扣门窗洞口，**洞口侧壁及顶面不增加**；不扣踢脚线、挂镜线、墙与构件交接处；附墙柱梁垛侧壁并入 | 取决于建模方式 | — |
| 墙面块料 | 按**实际镶贴表面积**（门窗侧壁按实计算） | 同上一行但口径相反 | **块料面积必然大于抹灰面积** |
| 天棚吊顶 | 按水平投影面积；灯槽、跌级、藻井**不展开不扣除**；只扣>0.3㎡孔洞、独立柱、与天棚相连窗帘盒 | 天花板面积 | 基本一致（不要自己去扣灯槽） |
| 土方 | 按设计图示尺寸，**不包括工作面与放坡**；天然密实体积 | 只能专项建模 | **与定额量差 20%~40%** |
| 土方定额 | **包含工作面、放坡、机械进出场坡道** | — | 同上 |
| 回填 | 挖方清单量 − 自然地坪以下埋设的基础体积 | 模型不提供 | 必须按公式计算 |
| 桩基 | 按桩长（含桩尖）或截面积×桩长 | 几何长度（有效桩长） | 成孔深度≠有效桩长≠设计桩长 |
| 管道 | 按中心线延长米，**不扣除阀门、管件及附属构筑物所占长度** | 管道与管件是分开的类别，管长不含管件 | **模型偏小 5%~15%** |
| 风管 | 按**展开面积**计算，**不扣除检查孔、测定孔、送风口、吸风口** | 面积字段通常已是展开面积 | 基本一致；弯头三通算法可能不同 |
| 电缆 | 按图示长度 + 规范规定的预留长度 | **通常不建模** | 必须按配管长度+根数+预留估算 |
| 支吊架 | 按质量或含在管道项目工作内容中 | **通常不建模** | 必须专项生成或规则估算 |

## 三、偏差的六类归因

| 类别 | 本质 | 是否「算错」 | 处理方向 |
| --- | --- | --- | --- |
| 建模原因 | 漏建、简建、类别错、材质空 | 是 | 修模型 |
| 口径原因 | 模型净量 vs 规则计算量 | **不是** | 建换算规则表并说明 |
| 工艺原因 | 搭接、充盈系数、切割损耗 | **不是** | 显式加系数，不要混进模型量 |
| 变更原因 | 变更未回写模型 | 是（流程问题） | 建立变更回写台账 |
| 数据原因 | 工作集、链接、阶段、版本 | 是（操作问题） | 按 QA 清单逐项排查 |
| 人为原因 | 手改导出文件、用旧版数据 | 是 | 禁止手改；标注取数版本 |

**把所有偏差都归为「建模误差」是最常见的归因错误。** 大量偏差其实是口径差或工艺差——这些不需要「修正」，需要的是「说明」。

## 四、分类型偏差基准值

| 构件类型 | 正常 | 需关注 | 重大 |
| --- | --- | --- | --- |
| 按「樘」/按个数计量的构件 | ≤1% | 1%~3% | >3% |
| 混凝土（分项） | ≤3% | 3%~8% | >8% |
| 混凝土（总量） | ≤2% | 2%~5% | >5% |
| 钢筋 | 10%~15% | 15%~20% | >20% |
| 钢结构（主体构件） | ≤3% | 3%~8% | >8% |
| 机电管道 | ≤5% | 5%~15% | >15% |
| 风管 | ≤5% | 5%~10% | >10% |
| 土方（清单 vs 定额） | 20%~40% | 40%~60% | >60% |
| 防水与保温 | ≤8% | 8%~20% | >20% |
| 装饰装修 | ≤5% | 5%~12% | >12% |
| 盾构管片（按环） | ≤2% | 2%~5% | >5% |
| 支吊架与抗震支架 | 无「正常偏差」概念，只能标注为估算量 | — | — |

**注意钢筋这一行**：10%~15% 是正常的。模型净量本该小于采购量——因为不含搭接、弯钩、损耗。有一个真实案例：per-bar 明细表总计 96 吨，加工厂实际下料 110 吨，差距不在公式错，而在三点（搭接未建模、三层柱箍筋被自动放成直筋形状、切割损耗）。所以**如果钢筋的模型量接近甚至超过采购量，反而要查是否重复计数**。

## 五、BIM 算量本身的能力边界（应如实告知委托方）

这不是「模型量不准」，而是工具定位问题：

1. **「一键出完整 BOQ」是误解。** 精度取决于「为算量而建模」（Modeling for Takeoff），而不是点一下按钮。
2. **目标冲突。** 为算量优化的模型（把抹灰、涂料拆成独立构件）对出图和可视化来说太重太复杂。同一个模型很难同时最优地服务两种用途。
3. **明细表计算能力有限。** 复杂逻辑必须导出到 Excel 处理，而一旦导出处理就破坏了 SSOT——多个版本随之出现。
4. **三类构件是明确的弱项**：钢筋（净量不含搭接损耗，且国内平法形状与锚固形式支持不足）、模板（无专用工具，用墙/板替代在接头搭接处不准）、装饰面层（提取面积可能不扣洞口，拆成独立构件又会让模型变重）。
5. **本地计算规则不直接支持。** 国内清单定额规则需要额外一轮调整；Revit 插件算量的原理是把 Revit 模型映射到算量模型，**构件定义与映射是否正确是量准不准的前提**。
6. **精度悖论。** 一方面给出「过度精确」的净量（无余量、无损耗），另一方面对真实施工标准和流程又「不够精确」。使用者不能盲信数字，必须回补规则与系数。

**说清这些边界不会削弱 BIM 算量的价值**——它的价值在于：图模量一体化、变更后自动更新、构件级可追溯、减少二次算量。但把边界说清，才不会在结算桌上被打脸。
