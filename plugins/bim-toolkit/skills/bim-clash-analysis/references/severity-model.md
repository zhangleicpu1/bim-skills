# 碰撞严重程度判级模型

Navisworks 原始报告**没有**严重等级字段 —— 它只给距离、状态、坐标和构件信息。本文件说明如何从这些原始字段推导出一个可用于排优先级的分值，以及怎么按项目调参。

## 一、为什么需要自建模型

碰撞协调会上最常见的困境是：一份报告几百上千个碰撞点，逐条看根本排不出优先级，结果往往是「谁先吵谁先改」。判级模型的作用是把「结构梁里穿了一根消防主管」和「两块装饰板轻微重叠」区分开来，让 P0 清单能直接进专题会。

判级只回答一个问题：**先改哪个**。它不替代设计判断，最终方案仍由专业负责人确定。

## 二、分值构成

```
严重度分值 = 碰撞类型基础分        (0 ~ 5)
           + 构件专业优先级分      (0 ~ 4)
           + 跨专业协调难度加分    (0 或 1.5)
           + 距离影响分            (0 ~ 3)
           + 关键区域加分          (0 或 1)
```

理论区间 0 ~ 14.5。

### 2.1 碰撞类型基础分

| 类型 | 分值 | 判定依据 |
| --- | ---: | --- |
| 硬碰撞 | 5.0 | 构件实体相互穿越，几何上必须调整 |
| 间隙碰撞 | 3.0 | 未穿透但净距小于容差，违反检修/保温/安全间距 |
| 重复项 | 1.0 | 构件重复建模，删除冗余模型即可 |
| 未知 | 4.0 | 报告未提供判定信息 |

硬碰撞分最高，因为它是**确定要改**的；间隙碰撞可能是容差设置偏严导致，需要人判断；重复项通常一键删除。

### 2.2 构件专业优先级

取碰撞双方中**较高**的一方。理由：结构与消防主管的碰撞，严重性由更关键的那一侧决定。

| 专业 | 优先级 |
| --- | ---: |
| 结构 | 10.0 |
| 机电-给排水消防 | 10.0 |
| 机电-暖通 | 9.0 |
| 设备 | 8.5 |
| 机电-电气 | 8.0 |
| 幕墙 | 7.0 |
| 建筑 | 6.0 |
| 机电-智能化 | 5.5 |
| 未知 | 5.0 |
| 景观场地 | 3.0 |

换算成分值：`(优先级 - 最低优先级) / (最高优先级 - 最低优先级) × 4`。按默认表即 `(p - 3) / 7 × 4`。

结构与给排水消防并列最高，是因为这两类碰撞往往牵涉承重安全与消防合规 —— 返工代价和审查风险都最大。

### 2.3 跨专业协调难度加分

碰撞双方属于**不同且已知**的专业时 +1.5。同专业内部碰撞由一个专业自己就能解决，跨专业需要协调会、会签、甚至设计变更，实际处理周期长得多。

### 2.4 距离影响分

上限 3 分，但**硬碰撞与间隙碰撞的方向相反**：

- **硬碰撞**：穿透越深越严重。`3 × min(穿透深度 / 30mm, 1)`。穿透 30mm 及以上得满分。
  理由：穿透 2mm 常常是建模精度问题，而穿透 300mm 往往意味着整根管道走了错误路由。
- **间隙碰撞**：净距越**小**越严重。`3 × max(0, (50mm - 净距) / 50mm)`。净距接近 0 得满分，净距 ≥ 50mm 得 0 分。
  理由：间隙碰撞的本质是「差一点就撞上」，净距越小风险越高。
- **重复项**：不计距离分，距离对它没有意义。
- **距离缺失**：记 0 分。

参考值 `30mm` / `50mm` 都是可配置的行业经验值，不同项目容差不同，应结合实际调整。

### 2.5 关键区域加分

碰撞点位于设备层、避难层、地下室、机房、屋面、核心筒、转换层等区域时 +1。这些位置管线密集、净高紧张、后期改动代价大。

楼层信息优先取源报告字段，缺省时从轴网标注（如 `3F / C-3`）或构件路径中的楼层关键词推断。

## 三、等级划分

| 等级 | 标签 | 阈值 | 建议处理要求 |
| --- | --- | ---: | --- |
| P0 | 严重 | ≥ 13.0 | 立即处理，影响结构安全或主干系统，须在下一版模型前闭合 |
| P1 | 高 | ≥ 10.5 | 优先处理，影响净高、检修空间或点位合规性 |
| P2 | 中 | ≥ 7.5 | 计划处理，纳入常规碰撞协调会跟踪 |
| P3 | 低 | < 7.5 | 低优先，可结合深化设计一并解决 |

阈值定得偏紧（P0 只留给真正的硬伤），目的是让 P0 清单短到能在一场会上过完。可以注意一个刻意设计的结果：**间隙碰撞几乎不会被判为 P0**（最高 3 + 4 + 1.5 + 3 = 11.5，加上关键区域加分也仅 12.5 < 13.0），因为间隙碰撞需要人工判断容差是否设置过严，不宜与实体穿越混为一谈。如果项目处于方案阶段、容差设得很严，可以整体上调阈值。

## 四、典型场景验算

| 场景 | 计算 | 分值 | 等级 |
| --- | --- | ---: | --- |
| 结构梁 × 消防主管，硬碰撞穿透 60mm，设备层 | 5 + 4 + 1.5 + 3 + 1 | **14.5** | 严重 |
| 结构梁 × 消防主管，硬碰撞穿透 8mm，3F | 5 + 4 + 1.5 + 0.8 | **11.3** | 高 |
| 结构梁 × 暖通风管，间隙净距 5mm | 3 + 4 + 1.5 + 2.7 | **11.2** | 高 |
| 建筑墙 × 电气桥架，硬碰撞穿透 12mm | 5 + 3.11 + 1.5 + 1.2 | **10.8** | 高 |
| 建筑墙 × 电气桥架，硬碰撞穿透 3mm | 5 + 3.11 + 1.5 + 0.3 | **9.9** | 中 |
| 建筑墙 × 暖通风管，间隙净距 45mm | 3 + 3.11 + 1.5 + 0.3 | **7.9** | 中 |
| 砌体墙 × 砌体墙，重复项 | 1 + 1.71 + 0 + 0 | **2.7** | 低 |

可以看出模型的倾向：**跨专业的硬碰撞天然排前面，同专业的重复项天然排后面**，符合实际协调会的工作顺序。

## 五、调参指南

改 `assets/severity_rules.json`，无需改代码：

| 想达到的效果 | 调整项 |
| --- | --- |
| 让 P0 清单更短/更长 | `severity_thresholds` |
| 本企业认为某专业更关键 | `discipline_priority`（同时改 `rules.py` 里的 `_FALLBACK_RULES` 保持一致，虽然正常流程只读 JSON） |
| 容差设得严，间隙碰撞不该排太高 | 提高 `severity_thresholds.P1`，或降低 `clash_type_base.间隙碰撞` |
| 深度穿透没有想象中严重 | 提高 `distance_model.hard_penetration_ref_mm` |
| 关键区域加分太重 | 把 `key_level_bonus` 调小或清空 `key_level_keywords` |
| 不需要跨专业加分 | 把 `cross_discipline_bonus` 设为 0 |

**调参后必须重跑并核对分布**。判级阈值一旦让 70% 的碰撞都变成 P0，模型就失去意义了 —— 合理的分布通常是金字塔形，P0 占比控制在 5%~20%。

## 六、已知局限

- **专业与类别靠关键词匹配**：构件命名不规范（如全是「零件1」「Part 22」）的项目会大量落入「未知」，此时判级退化为按碰撞类型和距离排序。解决办法是扩充 `discipline_keywords`，或推动项目统一命名。
- **距离符号推断碰撞类型不总是可靠**：部分模板导出的距离恒为正值。若源报告没有显式检测方式字段，建议从 XML 重新导出以拿到 `clashmethod`。
- **不含施工可行性与造价因素**：判级只看几何与专业，不含变更成本、工期影响、施工顺序。这些应由项目团队在 P0/P1 清单上人工补充。
- **楼层推断依赖命名**：构件路径不含楼层关键词时全部标为「未标注」，不影响判级主体逻辑，只影响楼层分布统计。
