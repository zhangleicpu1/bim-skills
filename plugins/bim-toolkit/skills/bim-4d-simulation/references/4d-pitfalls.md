# 4D 施工模拟的失败模式与校核方法

本文件汇总 4D 模拟在做完之后才发现问题、需要返工的五类失败模式，及其校核方法。内容来自行业实践与公开案例的整理。

---

## 一、临时设施只进不退，模拟变成动画片

### 现象

主体结构已经封顶，画面里的临时围挡、施工便道和塔吊却还原封不动。单看每个对象都没错，合在同一时点就失真了。

### 原因

临时设施只设置了「什么时候出现」，没有处理「什么时候退出」。如果任务类型全部用 Construct，它们在画面中永久存在。

### 后果

- 临时便道一直存在 → 永久道路施工的工作面被遮挡；
- 脚手架没有按阶段退出 → 幕墙和室外管网的空间关系被误判。

### 校核方法

把临时设施拆成**四个状态**来管理：

| 状态 | 要回答的问题 |
| --- | --- |
| 进场条件 | 它在什么前置工序完成后才能进场？ |
| 有效使用期 | 它服务哪些工作面、用到什么时候？ |
| 转换条件 | 什么条件下需要转换（堆场转场、便道改线）？ |
| 退场结果 | 退到哪里？退场后腾出的工作面给谁用？ |

评审时重点检查**三个时点**：临设使用前、使用中、退场后。

### 任务类型对应

- 临时设施全程存在 → **Temporary**
- 临时设施后期移除 → **Demolish**（盾构机拆解、支撑拆除、塔吊拆除）
- 永久工程 → **Construct**

★ 判定标准：**退场时间必须晚于其服务的工作面完成时间**。塔吊拆早了，外墙装修没有机械；拆晚了，占着室外工程的工作面。

## 二、模型能打开，不等于能做 4D

### 现象

模型导入后画面正常、构件也能选中，但计划任务导进来后找不到稳定的构件筛选条件；同一楼层的梁板柱名称各自为政。

### 后果

第一版也许能做完，但**第二版更新时很难说明哪些对象被漏掉了**。整个模拟的生命周期只有一版。

### 校核方法

检查模型是否具备「可筛选」的属性，至少能稳定区分五项：

1. 楼层
2. 专业
3. 构件类别
4. 施工区
5. 任务编码

属性名称还要统一——不要同时出现「3F」「三层」「Level 3」三套楼层写法。

**具体做法**：随机选取几个典型构件，确认能否按上述五项属性筛选出来。**如果模型只能靠人工框选，就先去补属性，不要急着往下做。**

## 三、计划任务和模型颗粒度对不上

### 现象

计划里的「二层结构施工」包含钢筋、模板、混凝土多个工序，模型却是按单个梁、板、柱组织的。直接把整层构件一次性挂到任务上，动画很流畅，但不能反映现场先后关系。

### 两种情形

| 情形 | 判断 | 处理 |
| --- | --- | --- |
| **模型颗粒度高于计划** | ✓ 不成问题 | 把多个构件聚合成集合，挂到同一条任务上 |
| **模型颗粒度低于计划** | ✗ 严重问题 | 一个构件要挂到多条任务上——只挂其中一条则看不到其他工序的先后；挂到每条任务上则该构件被反复建造与拆除，资源被重复计算 |

### 校核方法

先判断要把**任务拆细**还是把**构件按工作面组成选择集**。两种方式都可以，关键是**保留明确的映射依据**。

任务拆分要服从现场执行，选择集则要能够通过参数或命名**再次生成**。

对颗粒度低于计划的情形，折中做法是**自定义外观方案表达「未完成」状态**，直到该构件的最后一道工序结束。

## 四、时间不打架，空间打架更致命

### 现象

两个专业的任务条在时间上没有重叠，画面里却同时占用了同一工作面。

### 案例

某超高层项目，幕墙单位承诺 15 天完成标准层安装。推演时发现其**吊篮附墙件安装需占用塔吊附着牛腿位置**，而该位置已被主体结构施工预占——两者在时间轴上完全不冲突。

### 校核方法

跨单位、跨专业的进度推演必须**导入空间约束模型**：

- 施工机械站位与服务范围（塔吊幅度、履带吊站车位置）；
- 高空作业设备的附墙件位置（吊篮、爬架）；
- 材料堆场与运输道路的占用时段；
- 临时结构与永久工程的空间重叠（出土栈桥与水平支撑）。

★ 启用 **时间基碰撞检查（Time-Based Clashes）**：检查同一时点内空间上冲突的构件。这是唯一能自动发现这类问题的手段。

### 线性工程的额外问题

长距离线性工程（道路、管廊、隧道）按标准流程做整条走廊的 4D 模拟，会**缩放到根本看不清单个工序的程度**。

**处理**：按标段或按施工段分段设视角，分段导出，不要用一张全景图播全程。

## 五、动画比计划「跑得快」：项目日历规则不一致

### 现象

- 模型已经长到三层，计划表却还停在二层；
- 某项设备安装在周日继续播放，现场实际上周末停工；
- 两个专业的任务条没有重叠，画面里却同时占用了同一工作面。

### 原因

计划里的开始与完成日期只是**时间计算的结果**。结果背后还有一套规则：每周工作几天、每天几个班次、夜班是否跨日、节假日是否停工、某个阶段是否临时调整工作时间。

**计划软件与 4D 工具采用的日历规则不一致时，同样一项「5 个工作日」的任务，落到时间轴上的位置就可能不同。** 单看任务起止日期不一定能发现，连续播放 4D 序列时却很明显。

### 四件必须核对的事

| 核对项 | 要问的问题 |
| --- | --- |
| **工作周** | 主体结构是不是六天工作制？机电按五天制推进？夜间运输只在限定时段进行？ |
| **班次边界** | 夜班从晚上开始、凌晨结束，究竟计入哪一天？跨日任务与下一班次之间有没有留交接窗口？ |
| **例外日期** | 法定节假日、场地移交、重大检查、临时停电、受限施工时段是否已进入计划规则？ |
| **日历归属** | 日历挂在项目、任务，还是特定工作包上？总控计划与专业计划是否共用一套日历？ |

★ 例外日期不宜只写在会议纪要里，最好**进入可计算的计划规则**。学校（寒暑假与考试期）、医院（不能停诊）、市政（交通导改时段）类项目尤其重要。

### 校核顺序

1. 选一个**持续时间短、现场节奏明确**的样板任务（一段楼板施工、一个区域的设备吊装）；
2. **不要一开始就播放整个项目**；
3. 逐项核对：计划软件中的日历名称、工作周与班次设置；
4. 核对导入后任务的起止时间及持续时间；
5. 核对周末、夜间与例外日期是否仍按预期跳过或执行；
6. 样板任务通过后再检查其他任务。

## 六、六条通用原则

### 6.1 先写下一句话目标

> **这次模型需要帮助项目团队做什么决定。**

用于投标演示的 4D、用于月度计划协调的 4D、用于周计划和机械路径检查的 4D，**拆分深度并不一样**：

| 目标 | 粒度 | 典型任务量 |
| --- | --- | --- |
| 投标演示、领导汇报 | 按楼层 / 分部工程 / 标段 | 30~80 条 |
| 月度计划协调 | 按施工段 / 流水段 / 专业 | 200~600 条 |
| 周计划与机械路径 | 按流水段 × 工序 / 按机械作业面 | 1000 条以上 |

目标不清楚，模型团队往往会无限补细节，而计划团队却仍然只提供一张粗颗粒度横道图。

### 6.2 先做样板段，再扩展规则

参数质量未经验证时，不建议一开始就对整栋楼做自动挂接。

选一个**典型楼层或一个完整流水段**，先走通「筛选构件 → 建立任务 → 关联时间 → 检查结果」的闭环。样板段通过后，再把规则扩展到相似区域。

### 6.3 播放前检查未分配构件与重复关联

用「隐藏已链接构件」的方式检查：最后仍然可见的对象就是**孤儿构件**。

重复关联的构件会被反复建造与拆除，导致资源被重复计算。

### 6.4 判断重点是局部时间窗口

真正容易出问题的是**局部时间窗口**——某一周内结构施工与机电安装是否占用了同一作业面，临时道路是否在材料运输前被封闭。

不要只看整体趋势，要盯住少数几个关键时段逐帧看。

### 6.5 模拟结果「完全没有问题」= 值得警惕

一个做对了的 4D 模拟必然会查出冲突。若播放顺畅、挑不出问题，通常说明：

- 拆分深度不够；
- 关联不完整（有大量漏挂）；
- 只查了时间、没查空间。

### 6.6 4D 的成果是优化后的计划，不是视频

模拟跑完后必须回写进度计划，形成闭环。只输出一段视频，等于没有产出决策价值。

## 七、按阶段的自查要点

| 阶段 | 最容易漏的事 |
| --- | --- |
| 准备 | 模拟目标未写明；施工段划分依据未与施工方确认；模型属性无法稳定筛选 |
| 关联 | 任务与构件命名不一致；存在孤儿构件；构件被重复关联 |
| 任务 | 临时设施只设进场不设退场；养护、检修、停工期未占时间 |
| 时间 | 项目日历规则不一致；时间尺度失真 |
| 校核 | 只查时间冲突不查空间冲突；未使用时间基碰撞检查；结果「完全没问题」 |
| 交付 | 导出成一帧；交付格式不通用；只交付视频不交付计划与冲突清单 |
