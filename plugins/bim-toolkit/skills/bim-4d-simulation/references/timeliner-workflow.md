# Navisworks TimeLiner 操作详解

本文件是 `scripts/sim_builder.py` 生成的方案中「TimeLiner 操作步骤」一节的展开说明，供执行时查阅。

---

## 一、为什么会「做不准」

4D 模拟的失败极少发生在动画功能上。真正的失败发生在更早的环节：**模型数据、进度计划和现场分区没有使用同一套语言**。

典型表现：

- 模型导入后画面正常、构件也能选中，但计划任务导进来后**找不到稳定的构件筛选条件**；
- 同一楼层的梁板柱名称各自为政，出现「3F」「三层」「Level 3」三套写法；
- 现场按流水段施工，模型里却没有施工区属性。

这些问题在做第一版时不一定暴露，但**第二版更新时会彻底失控**——因为无法说明哪些构件被漏挂了。

所以流程的第一阶段（前置准备）不在 Navisworks 里做，却决定了成败。

## 二、前置准备（在 Revit / 计划软件中完成）

### 2.1 统一属性语言

建模前必须确定并在全模型内统一：

| 属性 | 要求 | 反例 |
| --- | --- | --- |
| 楼层 | 一种写法 | `3F` / `三层` / `Level 3` 混用 |
| 施工区域 | 与现场流水段一致 | 模型按轴线分区，现场按后浇带分区 |
| 专业 | 建筑 / 结构 / 给排水 / 暖通 / 电气 / 弱电 | 简写不统一 |
| 构件类别 | 用 Revit 原生类别 | 自定义类别导致统计失效 |

### 2.2 写入关联主键

这是能否自动重建关联的关键。推荐写入的共享参数：

- **施工区域**：与现场流水段编号一致
- **流水段号**：如 `A-3F-02`
- **任务编码 / Activity ID**：与计划软件中的活动 ID 一一对应（盾构隧道用环号、管廊用桩号、基坑用地连墙槽段编号）

写入方式：Revit 中用 Dynamo 按空间坐标或按已有的楼层/区域参数批量写入。**不要指望建模人员手工逐个填写**——上千个构件的项目必然漏填。

### 2.3 准备进度计划

- 从 Project / P6 / Asta 导出为 CSV 或直接使用原生格式；
- **检查任务名或任务编码能否与模型主键对应**——对应不上，后面只能靠人工框选；
- 取得项目日历的书面说明（工作周、班次、例外日期）；
- 任务类型（Construct / Demolish / Temporary）如有，建议单独成列以便映射。

## 三、导入与关联

### 3.1 数据源（Data Sources 选项卡）

| 操作 | 位置 | 说明 |
| --- | --- | --- |
| 添加数据源 | 「数据源」选项卡 → 「添加」 | 支持 Microsoft Project、Primavera P6、Asta Powerproject、CSV、MPX |
| 字段映射 | 「字段选择器」对话框 | 把 TimeLiner 的列映射到外部文件字段 |
| 重命名数据源 | 右键数据源 → 重命名 | 多个数据源时便于区分，建议用标段名或文件名 |
| 重建任务层次 | 右键数据源 → Rebuild Task Hierarchy | 导入任务；弹「导入数据中的问题」时须逐条核对缺失字段 |

**Rebuild 与 Synchronize 的区别（重要）**

- **Rebuild**：按外部数据重建全部任务，**手工调整会被覆盖**；
- **Synchronize**：保留手工修改。

一旦开始手工关联，后续更新必须用 Synchronize，否则手工的工作全部作废。

### 3.2 建立关联

**主路径：规则自动关联**（「任务」选项卡 → 使用规则自动附着）

- 勾选「将 TimeLiner 任务从列名映射到**同名选择集**」（或映射到图层）；
- **Matching case（区分大小写）必须勾选**，否则会误匹配；
- 前提：任务名与集合名严格一致。

**副路径：手工补充**（仅用于少量零散构件）

| 方式 | 适用 | 说明 |
| --- | --- | --- |
| 附着当前选择 | 个别构件 | 先在模型视图中选中构件，再右键任务附着。效率低，不可批量使用 |
| 附着当前搜索 | 按属性筛选结果 | 用「查找项目」按属性筛选后整体附着 |
| 附着集合 | 已有集合体系 | 从选择集/搜索集列表中选取 |
| 拖放 | 少量 | 从选择树拖到任务上 |

**搜索集 vs 选择集**

- **搜索集（Search Set）**：按条件动态生成，**模型更新后仍有效**；
- **选择集（Selection Set）**：静态快照，**模型一改就失效**。

★ 优先用搜索集。这不是效率问题，而是可维护性问题。

### 3.3 关联完整性检查

1. 看「附着」列：有内容即为已挂接；
2. **隐藏所有已挂接构件**，视图中仍然可见的即为**未被任何任务引用的孤儿构件**——这是最可靠的漏挂检查法；
3. 检查同一构件是否被挂到多条任务上（重复关联会导致构件反复建造/拆除，资源被重复计算）。

## 四、任务类型与外观定义

### 4.1 三种任务类型

| 类型 | 含义 | 用法 |
| --- | --- | --- |
| **Construct** | 建造 | 永久工程；构件从无到有并保留 |
| **Demolish** | 拆除 | 已存在构件被移除；用于临时设施退场、支撑拆除、盾构机拆解 |
| **Temporary** | 临时 | 全程存在但属临时性质；用于塔吊、脚手架、围挡、便道 |

★ **临时设施必须用 Temporary 或 Demolish。** 若全部用 Construct，它们会永远留在画面里——这是「4D 模拟变成动画片」最常见的成因。而且临时设施遮挡永久工程的工作面，会导致空间关系误判。

注意：这三种类型是 **Navisworks 的软件功能**，不是规范条文。交付文件中应把软件实现方式与标准要求分开表述。

### 4.2 外观定义（Configure 选项卡）

可为任务类型配置：Start Appearance / End Appearance / Early Appearance / Late Appearance / Simulation Start Appearance。

★ **Early / Late 外观是把 4D 从「动画」升级为「进度分析工具」的关键**：用两种外观分别表示「计划完成」与「实际（或预计）完成」，即可直观呈现进度偏差，对应 Simulate 中的 Planned against Actual 视图模式。

## 五、模拟与校核

### 5.1 模拟设置（Simulate 选项卡 → 设置）

- **时间与间隔**：按天 / 周 / 月。间隔要与模拟目标匹配——L1 演示可按周，L3 校核必须按天；
- **播放速度**：总工期跨月时，速度调太快看不出工序关系。建议按「每 2~3 秒过一个关键阶段」试配；
- **跟随动画（Animation）**：Orbit（环绕）、Fly（飞行）等预设。汇报用环绕，**校核分析建议固定机位**；
- **视图模式**：Planned against Actual，用于表达进度偏差。

### 5.2 校核（4D 真正的价值）

**时间基碰撞检查（Time-Based Clashes）**

这是 4D 与碰撞检测结合的产物：检查同一时点内空间上冲突的构件。它能查出「两个作业面在同一时间占用同一空间」这类**纯时间分析或纯空间分析都发现不了**的问题。

**工作面占用核对**

对时间上并行的任务，核对是否占用同一工作面（同一楼层、同一区域、同一运输通道）。跨单位（总包与专业分包）的进度推演**必须纳入空间约束**：机械站位、吊篮附墙件位置、材料堆场、临时便道。

> 一个真实教训：某超高层项目幕墙单位承诺 15 天完成标准层安装，推演时发现其吊篮附墙件安装需占用塔吊附着牛腿位置，而该位置已被主体结构施工预占。这类冲突在时间轴上完全看不出来。

**临时设施进退场核对**

重点看三个时点：**临设使用前、使用中、退场后**。

- 主体已封顶，塔吊还立着？
- 永久道路已通车，临时便道还在？

**日历规则核对**

详见 `references/4d-pitfalls.md` 第二、三节。

### 5.3 校核的一个反直觉判断

**如果模拟结果「完全没有问题」，通常说明拆分深度不够或关联不完整，而不是工程真的没问题。**

一个做对了的 4D 模拟必然会查出若干冲突。若播放顺畅、挑不出问题，应回头检查：是否有大量孤儿构件、任务颗粒度是否过粗、是否只查了时间而没查空间。

## 六、NWD 交付的坑

多个 NWD 文件合并时，**只会保留第一个文件中的 TimeLiner**，其余文件的 TimeLiner 会被忽略。

正确流程：

1. 对每个 NWD 分别打开 TimeLiner；
2. 「导出到集合」（Export to Sets）；
3. 「任务」选项卡 → 导出计划（Export Schedule）→ 选 CSV；
4. 保存 NWD；
5. 新建文件，合并（Append / Merge）多个 NWD；
6. 「数据源」选项卡 → 添加 → 导入 CSV 数据 → 做列映射；
7. 右键数据源 → 重建任务层次；
8. 「任务」选项卡 → 使用规则自动附着 → 勾选「从列名映射到同名选择集（区分大小写）」→ 应用规则。

## 七、操作模式切换的四个模式

综上，TimeLiner 的操作可归纳为四个模式，交替使用：

1. **数据源模式**——导进度、调映射、重建层次；
2. **任务模式**——建任务、定类型、挂构件、查漏挂；
3. **配置模式**——定外观、区分在建与已完；
4. **模拟模式**——设时间与视角、播放、导出。

前两个模式决定「准不准」，后两个决定「有没有用」。
