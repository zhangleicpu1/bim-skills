# BIM 答辩 PPT 生成助手

## 这个 Skill 解决什么问题

答辩 PPT 的技术门槛不高，**难点是「内容取舍」和「经得起追问」**。

本 Skill 的核心立场：**答辩 PPT 不是成果的堆砌，而是一条能被评委反复追问的主线。** 评委看的不是「你做了多少」，而是「你为什么这么做、做得对不对、还差什么」。每一页如果去掉后不影响主线成立，它就不该出现在台上——应移到附录备用页，等被问到再翻出来。

因此本 Skill 不只是「给一个 PPT 目录」，而是同时交付三样东西：

1. **每页的内容要点**——这一页要放什么
2. **每页的演讲备注**——这一页要怎么讲（含时长、要强调什么、绝不能说什么）
3. **提问预案**——评委最可能问什么、怎么答、陷阱在哪

## 触发方式

- 「帮我生成 XX 项目的答辩 PPT」
- 「答辩 PPT 大纲怎么写」「我的答辩 PPT 该怎么组织」
- 「答辩怎么准备」「时间怎么分配」「讲稿怎么写」
- 「评委可能问什么问题」「答辩会问什么」「怎么回答」
- 「答辩 PPT 怎么排版」「字号多大合适」

## 工作流程

1. **识别项目方向**——7 类，别名自动归一（69 个别名，含「管廊」「地连墙」「叠拼」「牌坊」等口语说法）；未收录方向回退通用骨架并明确标注需人工补充；歧义说法会提示备选方向
2. **确认用户输入**——项目名称、方向、核心成果、创新点。核心成果与创新点会注入到对应页面，并提醒用户核对每条成果的可追溯性
3. **输出 PPT 大纲**——12 页页面库（封面 / 目录 / 背景 / 技术路线 / 模型展示 / 碰撞检测 / 4D 模拟 / 工程量统计 / 创新价值 / 反思总结 / 致谢 / 附录备用页），每页给出优先级（必有 / 加分 / 可选）、按汇报时长自动折算的建议时长与占比
4. **输出每页内容要点与演讲备注**——页面卡片式呈现，左栏内容要点、右栏演讲备注，另附必备项、视觉建议、常见失误
5. **叠加该方向专属内容**——专属加分页（每方向 2 个）、可引用的量化指标（每方向 6 项）、必背术语、本方向最容易翻车处
6. **输出评委提问预案**——前 5 问（方向高频追问 4 条 + 通用最高频 1 条）+ 八类 34 问完整题库 + 5 类刁钻问题应对 + 提问类型分布（用来说明准备时间该花在哪）
7. **输出答辩准备建议**——应答黄金五步、三档时间分配、三阶段演练、材料与现场准备、10 条致命错误、7 条应急预案
8. **生成四份文件**——HTML 方案书（6 章，可打印）、Markdown 大纲、逐页讲稿卡（打印随身版）、提问预案与准备建议

## 命令行用法

脚本路径：`scripts/defense_builder.py`，**纯 Python 标准库，零依赖**。

```bash
PY="C:/Users/52248/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
S="<skill_dir>/scripts/defense_builder.py"

# 查看方向库与页面库
"$PY" "$S" --list

# 按方向生成（别名可用）
"$PY" "$S" --direction 铀矿巷道 --project "XX铀矿巷道工程" \
    --achievements "巷道全长3.2km|碰撞解决47处|4D优化工期12天" \
    --innovations "自建巷道参数化族库|通风与辐射分区联动" \
    --minutes 15 -o 输出目录

# 自定义输入（字段名见下方「输入结构」）
"$PY" "$S" --input data.json -o 输出目录

# 空白模板：all / outline / qa / prep
"$PY" "$S" --template outline --name "答辩PPT大纲模板" -o 输出目录

# 机器可读结果
"$PY" "$S" --direction 教学楼 --json-only
```

## 输出内容结构（HTML 方案书 6 章）

1. **答辩定位与时间分配**——项目信息、一句话主线、用户提供的成果与创新点、按分钟数自动折算的时间分配表（含占比）、时间铁律
2. **PPT 大纲总览**——12 页骨架表（页序 / 页面 / 优先级 / 这一页的任务）
3. **逐页内容要点与演讲备注**——12 张页面卡片，每张含内容要点、演讲备注、必备项、视觉建议、常见失误
4. **方向专属加分页与量化指标**——2 个专属加分页 + 6 项量化指标 + 必背术语 + 本方向最容易翻车处
5. **评委可能提问**——前 5 问（含提问意图 / 回答框架 / 陷阱 / 可能追问）、提问类型分布、八类 34 问完整题库、刁钻问题应对
6. **答辩准备建议**——应答黄金五步与五禁、三档时间分配、三阶段演练、材料清单、10 条致命错误、7 条应急预案

## 几个关键设计（使用时需要理解）

### 1. 页面优先级是「必有 / 加分 / 可选」，不是页数

时间不够时，**按优先级砍，不要按顺序砍**。附录备用页权重为 0（不讲，只备查）。时间紧张时优先砍「可选」，绝不能砍「必有」——尤其不能砍创新价值页与反思页，这两页决定评分。

### 2. 时间分配按权重自动折算，且内置两条硬约束

页库权重合计 81，脚本按 `--minutes` 折算每页分钟数。同时内置两条铁律并会主动提示：

- **项目背景 ≤ 总时长 10%**（15 分钟汇报 ≈ 1.5 分钟）
- **核心应用（模型 / 碰撞 / 4D / 算量）合计 ≥ 50%**

答辩最常见的事故不是讲得不好，是把时间耗在背景上、核心应用被压缩到仓促收场。

### 3. 「重难点 ↔ 应用点」的对应关系是全篇的骨架

背景页列出的重难点，是后面每一个 BIM 应用点的靶子。**如果应用点对不上任何重难点，它就是这个项目的堆砌。** 竞赛评审最反感的一句话是「这份作品换个项目也能用」——自查方法：把项目名和几张图换掉，整份汇报是否依然通顺。

### 4. 方向专属页是拉开差距的地方

7 个方向各配 2 个专属加分页，例如：

- **铀矿巷道** → 通风与辐射防护分区模拟（普通地下工程做不出来的内容）
- **综合管廊** → 标准断面与管线入廊排布（分舱原则是管廊的心脏）
- **盾构隧道** → 管片环建模与拼装逻辑（楔形量、错缝拼装）
- **基坑支护** → 分层开挖与工况模拟（先撑后挖、随挖随撑）
- **英雄纪念碑** → 石材排版与建造可行性（排版成果手算几乎做不了）

### 5. 提问预案的第一层是「方向高频问」，不是通用题库

「前 5 问」= 该方向的高频追问（4 条）+ 通用最高频的「你的创新点是什么」（1 条）。方向问题优先，因为评委会围绕你讲的项目追问，而不是问通用套路。完整题库按八类组织，配合**提问类型分布**（方法 30% / 数据 25% / 背景 20% / 创新与局限 15% / 应用展望 10%）说明准备时间该往哪投。

### 6. 量化指标给的是「该准备哪一类指标」，不是可以直接念的答案

每个方向 6 项指标（含建议量级），但方案书会明确标注：**指标值必须换成项目的真实数字**。报出来的每个数字都要能说出出处——答不出出处的数字，比没有数字更伤。

### 7. 反思页与不足是必答项，不是可选项

「主动讲不足比被问出来更得分。评委反感的不是『你有不足』，而是『你不知道自己有不足』。」方案书会明确要求准备 2-3 条具体的、技术性的不足，每条配一条可执行的改进方向。说「本项目没有不足」被列为最严重的减分项之一。

### 8. 所有占位符以红色〔待补充〕标出

知识库中凡需用户填实的内容（工程规模、量化指标、进度数据）统一用〔待补充〕标注并标红，避免用户把经验值当成自己的数据直接念出去。

## 知识库（唯一数据源）

- `assets/defense_kb.json`（66 KB）——`meta`（核心立场、优先级图例、时间铁律）+ `page_library`（12 页 × 角色 + 权重 + 内容要点 + 演讲备注 + 视觉建议 + 必备项 + 常见失误，合计 51 条要点、33 条备注、30 条失误）+ `directions`（7 类 × 别名 + 答辩主线 + 2 个专属加分页 + 6 项量化指标 + 4 条高频追问 + 术语 + 翻车点，共 69 个别名）+ `generic_fallback`
- `assets/qa_bank.json`（31 KB）——`probe_distribution`（提问类型占比）+ `answer_rules`（应答五步 + 五禁）+ `categories`（8 类 34 问，每问含提问意图 / 回答框架 / 陷阱 / 可能追问）+ `trap_questions`（5 类刁钻问题应对）+ `prep`（时间分配 3 档 / 演练 3 阶段 / 材料 3 组 / 10 条致命错误 / 7 条应急预案）
- `references/slide-design-guide.md`——PPT 排版硬规则（字号 / 字数 / 配色 / 图表选择 / 模型截图要求 / 动画克制 / 标题写成结论）
- `references/defense-countdown.md`——T-7 到 T-0 倒排时间线 + 当天现场检查表

**扩展方式**：加方向只需在 `defense_kb.json` 的 `directions` 里加一个键，方案书与提问预案自动支持；加问题只需改 `qa_bank.json`；加页面只需改 `page_library`。**不用动代码。**

## 故障排查

| 症状 | 处理 |
| --- | --- |
| 方向识别成「BIM 应用（通用方向）」 | 该说法不在 69 个别名内。看 `--json-only` 的输出确认，或直接改用 7 类的标准名；也可在 KB 的 `aliases` 里补充 |
| 方案里出现「该说法在库中挂多个方向」 | 属真实歧义。用该方向的标准名重新生成 |
| 时间分配看起来不合理 | 时长比例是**比例参考**而非标准答案。核心是保持「背景 ≤10%、核心应用 ≥50%」这个比例关系 |
| 想改汇报时长 | 加 `--minutes 20`（支持 10 / 15 / 20，也可用 `--input` 里的 `minutes` 字段） |
| 想只出大纲 / 提问预案 | `--template outline` / `--template qa` / `--template prep` |
| 需要打印 | HTML 已含 `@media print` 样式，直接浏览器打印；建议 A4 纵向 |
