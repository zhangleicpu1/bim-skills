# 参数化族创建助手

## 用途

把「我要创建 XX 构件的参数化族」转成一份可以直接照着做的建族方案 + 可勾选检查清单。

覆盖 12 类构件：防护门、锚杆、盾构管片、支护结构（钢支撑/围护桩/地连墙）、结构柱与框架梁、MEP 管线与管件、支吊架、设备基础、栏杆扶手、监测点标记、幕墙嵌板、楼梯与坡道。其他构件走通用骨架。

---

## 触发方式

- 「我要创建 XX 构件的参数化族」
- 「XX 构件的族怎么建」/「这个族该定义哪些参数」
- 「防护门/锚杆/管片/支护结构 的族怎么建」
- 「族改了参数几何乱跳 / 出现约束警告怎么办」
- 「给我一份族创建检查清单」

---

## 执行流程

### Step 1 · 识别构件

归一化构件名后查 `assets/component_library.json`。

**命令**：

```bash
python scripts/family_builder.py --list
```

别名自动归一：「铅门/CT室门」→防护门、「土钉/锚索」→锚杆、「隧道管片」→盾构管片、「地连墙/围护桩/钢支撑」→支护结构、「测斜管」→监测点标记。

别名匹配采用三级策略（精确 → 长别名包含 → 长别名优先），**单字别名不参与子串匹配**——否则「桥梁支座」会被别名「梁」误命中到结构柱与框架梁。

### Step 2 · 生成方案

```bash
# 按构件生成（参数清单从知识库带出）
python scripts/family_builder.py --component 管片 --project "XX地铁区间" -o 输出目录

# 用自定义参数覆盖/扩展（主路径）
python scripts/family_builder.py --input family_spec.json -o 输出目录

# 只要空白检查清单
python scripts/family_builder.py --template -o 输出目录
```

输出三份：
- **`{名称}_族创建方案.html`** — 完整方案，含参数清单表格（类型/实例彩色标签、必填标红）、9 步流程卡片、14 条错误排查卡片，可直接打印
- **`{名称}_族创建方案.md`** — 同内容 Markdown 版
- **`{名称}_族创建检查清单.md`** — 63—66 项可勾选清单

### Step 3 · 按方案交付

方案包含十节，交付时按节说明：

| 节 | 内容 |
| --- | --- |
| 一、构件与族样板 | 族类别、族样板、宿主关系、目标 LOD、建议文件名 |
| 二、参数清单 | 按分组排列，标注类型/实例、数据类型、单位、必填、填写说明 |
| 三、几何构建思路 | 该构件的具体建模手法 |
| 四、Revit 创建步骤 | 9 步标准流程 + 每步检查点 |
| 五、构件专属要点 | 该构件的关键设计注意 |
| 六、构件专属错误提醒 | 该构件特有的坑（如管片漏建楔形量） |
| 七、命名规范 | 文件命名、参数命名、标准依据 |
| 八、测试方法 | 10 项测试及通过标准 |
| 九、通用常见错误提醒 | Top 14 错误的现象/根因/处理/预防 |
| 十、发布前提醒 | 8 条原则性提醒 |

## 输入格式（`--input` JSON）

未提供的键自动从知识库与规范文件补全，只需填要覆盖的部分：

```json
{
  "component": "管片",
  "project_name": "XX地铁区间",
  "category": "常规模型",
  "family_template": "公制常规模型.rft",
  "hosting": "不基于宿主",
  "lod": "LOD350",
  "discipline": "隧道结构",
  "file_name": "TL-SEC-盾构管片-φ6200-LOD350.rfa",
  "geometry_approach": "几何构建思路的自定义描述",
  "key_points": ["本项目特有的关键点"],
  "pitfalls": ["本项目需要特别注意的坑"],
  "parameters": [
    {"name": "参数名", "kind": "类型", "data_type": "长度",
     "group": "尺寸标注", "unit": "mm", "required": true, "note": "说明"}
  ]
}
```

`kind` 取 `类型` 或 `实例`，`required` 为布尔值。

## 关键设计取舍（别丢）

1. **`kind`（类型/实例）在参数表里用彩色标签区分**。这是全流程唯一不可逆的决策——创建后无法更改，选错只能删除参数重建并重新关联几何。方案里对每个参数都注明类型/实例，并给出判断规则：**「现场 10 个构件这个值一样吗？一样→类型，不一样→实例」**。

2. **必填参数标红**。标为 `必填` 的参数是那些「影响明细表统计」或「影响多专业协同」的字段——如防护门的铅当量、管片的楔形量、钢支撑的预加轴力、监测点的预警值。这些漏了，模型在后续环节就废了。

3. **构件专属陷阱与通用错误分开**。方案第六节是该构件特有的坑（管片漏建楔形量会导致模型直的、隧道是弯的），第九节是跨构件的通用错误（几何锁到几何、参数类型选错）。两者性质不同，混在一起讲会稀释重点。

4. **9 步流程强调顺序不可颠倒**。底层逻辑是「参照平面控制尺寸 → 尺寸控制参数 → 参数控制几何」。第 4 步特意安排「此时还没有几何」的弯曲测试——这是最省力的排错时机，几何建完再测，问题会被掩盖。

5. **命名规范区分「标准依据」与「工程惯例」**。GB/T 51269-2017 是国标，编码结构与示例可直接引用；而「专业代号-类别缩写-名称-规格-LOD」这套文件命名格式是行业惯例，**国标并未规定**——方案里如实区分，不把惯例说成标准。

## 扩展知识库

`assets/component_library.json`（构件参数）与 `assets/family_standards.json`（规范）是唯二数据源：

- **加构件**：往 `components` 下新建键，**务必补齐 `aliases`**（否则用户换个说法命不中）；字段照现有构件结构填
- **加子类型**：用 `sub_types` 字段（如支护结构下的钢支撑/围护桩/地连墙），脚本会自动为每个子类型渲染独立参数表
- **加通用错误**：往 `family_standards.json` 的 `common_errors` 追加，`rank` 决定排序
- **加检查项**：往 `checklist_sections` 对应分节的 `items` 追加

新构件若没有专属参数，脚本自动回退到 `generic_fallback` 骨架，不会报错。

## 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 方案标「未在库内·需自行补参数」 | 正常。按 `references/parameter-design.md` 自行设计参数，或把该构件补进知识库 |
| 构件名命不中（如「桥梁支座」） | 未收录。这是**刻意设计**——单字别名不参与子串匹配，避免「梁」误命中「桥梁支座」 |
| 参数分组显示异常 | 检查 `group` 值是否在 `family_standards.json` 的 `param_groups` 列表中 |
| 检查清单项数差异 | 属正常：不同构件的专属陷阱与关键点数量不同，通用项固定为 63 项 |

## 三条不可越过的技术红线

1. **族样板决定一切，且不可逆**。不要从「公制常规模型」开始建再改类别——类别行为、剪切能力、连接件、分析模型不会完整转换。另外常规模型类别统计不到长度/体积/宽度，只能统计个数。
2. **参数类型（类型/实例）创建后不可更改**。选错只能删除重建。没有例外。
3. **永远不要把几何锁到几何，只锁到参照平面或参照线**。这是 Revit「约束不可预测」警告的唯一根因。修复的方向是删除冗余锁定，而不是加新约束。
