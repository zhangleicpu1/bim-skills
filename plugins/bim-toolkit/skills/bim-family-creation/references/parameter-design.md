# 参数设计原则（parameter-design）

参数是族的灵魂，几何只是外壳。这一节回答：**该建哪些参数、每个参数该用什么类型、怎么让它们不打架。**

---

## 一、第一决策：类型参数还是实例参数

这是全流程**唯一不可逆**的决策——创建后无法更改，选错只能删了重建，还要重新关联所有几何。

**决策规则**：

> 问自己：**现场有 10 个这种构件，它们的这个值会一样吗？**
> 一样 → 类型参数（Type）
> 不一样 → 实例参数（Instance）

**对照表**：

| 参数性质 | 应选 | 例 |
| --- | --- | --- |
| 规格、截面尺寸 | 类型 | 管片外径 φ6200、梁截面 300×700、管径 DN100 |
| 等级、牌号 | 类型 | 混凝土 C30、钢材 Q355、防护等级 Pb2 |
| 性能指标 | 类型 | 铅当量 2mmPb、预加轴力 500kN、传热系数 |
| 材质 | 类型 | 门扇材质、管片材质（同规格同材质） |
| 构造做法 | 类型 | 接头形式、开启方式、是否抗震 |
| **标高、定位** | 实例 | 支撑标高、桩顶标高、测点埋深 |
| **长度、跨度** | 实例 | 杆体总长、支撑长度、梁长、基础顶面标高 |
| **编号、位置** | 实例 | 测点编号、槽段编号、构件编号 |
| 局部尺寸 | 视情况 | 门槛高度（同型号不同房间可能不同）→ 实例 |

**两个高频错误**：

1. **把长度做成类型参数**（如锚杆杆体总长、钢支撑长度）
   → 每根长度不同，会建出几十个族类型，无法维护。**这是最常见的错误。**

2. **把材质做成实例参数**
   → 同规格构件的材质本应统一，做成实例后每个都要单独赋值，且材料统计会混乱。

## 二、参数的数据类型（数据/参数类型）

| 类型 | 适用 | 注意 |
| --- | --- | --- |
| 长度 | 尺寸 | 单位按项目设置，中国习惯 mm |
| 角度 | 倾角、转角 | **锚杆倾角、管片封顶块角度必须用此类型**，否则明细表提不出角度 |
| 整数 | 数量 | 分块数、螺栓数量、踏步数 |
| 数值 | 无单位量 | 铅当量、传热系数、比例值、阈值 |
| 文本 | 规格描述 | C30、Q355、Pb2、『6+12A+6 中空玻璃』 |
| 是/否 | 开关 | 可见性、开向、是否含闭口器、是否抗震 |
| 材质 | 材质 | 必须与几何的材质属性绑定才算数 |
| 族类型 | 嵌套族选择 | 选择不同轮廓类型 |
| 面积 / 体积 | 工程量 | 用于统计 |

**常见错误**：把倾角做成「数值」或「文本」而不是「角度」。
后果：无法用角度尺寸标注驱动，明细表也无法按角度筛选排序。

## 三、参数分组方式

分组影响参数在属性面板中的显示位置，以及明细表字段的组织方式。

| 分组 | 放什么 |
| --- | --- |
| 尺寸标注 | 所有几何尺寸参数 |
| 标识数据 | 型号标记、构件编码、防护等级、监测类型 |
| 材质和装饰 | 各类材质参数 |
| 图形 | 可见性开关、颜色标记 |
| 结构 | 强度等级、配筋、预应力、荷载 |
| 机械 | MEP 族的压力、流量、连接件 |
| 能量分析 | 传热系数、透射比等能耗参数 |
| 阶段化 | 施工阶段相关 |

## 四、公式：什么时候用，什么时候别用

**该用**：存在确定的数学关系时。

```
管片内径 = 管片外径 − 2 × 管片厚度      ✓ 避免三个数不一致
锚杆总长 = 锚固段长度 + 自由段长度       ✓ 避免改一个忘一个
管片块数间隔 = 360° / 分块数             ✓ 避免逐块手填
```

**不该用**：关系不确定或会引入过约束时。

```
❌ 用公式强行联动两个本该独立的尺寸
❌ 公式中引用尚未赋值的参数（出现 # 或 0 值传播）
❌ 用复杂嵌套公式替代可选参数（可读性极差，团队无法维护）
```

**原则**：公式只用于表达**设计中客观存在的约束**，不用于「省事」。
一条公式写下去，三个月后别人（包括你自己）必须能看懂它在表达什么。

## 五、约束的正确写法

约束的层级必须严格是：

```
参照平面 ←─锁定─ 几何
参照平面 ←─尺寸/参数─ 参照平面
```

**绝对不要**：

```
几何 ←─锁定─ 几何        ❌ 触发「约束不可预测」警告
```

**EQ（等分）约束的正确用法**：

```
✓ 在参照平面之间做 EQ
❌ 直接在几何之间做 EQ
```

原因：**Revit 不允许参照平面被几何图元推动**。如果 EQ 串里混进了几何参照，改尺寸时就会出现「约束未满足」。

**正确做法**：在需要等分的位置先补参照平面，用锁定/参数尺寸控制这些参照平面的位置，再在参照平面之间做 EQ。

## 六、共享参数：什么时候必须用

**族参数只在当前族内有效，出了这个族就没了。**

以下情况必须使用**共享参数**（需要独立的共享参数文件 `.txt`）：

| 场景 | 为什么 |
| --- | --- |
| 构件编码（按 GB/T 51269-2017） | 需要跨族跨项目统一，且要随 IFC 导出保留 |
| 制造商、型号、资产编号 | 运维阶段的数据挂接主键 |
| 运维信息（保修期、维护周期） | 交付运维阶段使用 |
| 需要进入项目参数或明细表的自定义字段 | 族参数无法在项目参数中引用 |

**配置方式**：管理 → 共享参数 → 指定共享参数文件（`.txt`）→ 创建参数并归入相应分组。
之后通过「项目参数」把它加到项目中，才能在所有构件上统一填写。

**注意**：共享参数文件是团队级资产，必须统一存放并版本管理，不要各自建各自的。

## 七、参数设计自查清单

设计完参数后，逐条过一遍：

- [ ] 每个参数都能回答「它驱动什么几何或被谁使用」
- [ ] 类型/实例属性逐个确认过（问过「10 个构件这个值一样吗」）
- [ ] 长度、标高、编号类参数已确认为实例参数
- [ ] 规格、等级、材质类参数已确认为类型参数
- [ ] 数据类型正确（角度类没有误用数值/文本）
- [ ] 参数分组方式选择合理
- [ ] 同一概念在不同族中命名一致
- [ ] 没有新建参数覆盖 Revit 内置参数名
- [ ] 公式只表达了客观存在的约束，没有为省事而写
- [ ] 需要跨项目复用的字段用了共享参数
- [ ] 关键参数都能进明细表（这一点要在建族前就验证）
- [ ] 参数总数合理——不是为了参数化而参数化，用不上的参数就是负担
